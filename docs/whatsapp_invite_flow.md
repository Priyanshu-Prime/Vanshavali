# WhatsApp Invite Deep-Link Flow — Shared Contract (v1)

This is the single source of truth that the landing page, the app, and CI/CD all
build against. Do not change a value here without updating every consumer.

## Why a hosted page (not a raw deep link on WhatsApp)
The app is not on the Play Store, so invitees sideload the APK. A raw
`vanshavali://` link won't render as clickable in WhatsApp and dies silently if
the app isn't installed. So WhatsApp carries an **https page** that (a) explains
the invite, (b) offers the APK download, (c) opens the app with the code once
installed, and (d) always shows the code for manual entry.

**Known limitation (by design):** fully-automatic code fill with *zero* taps
after a sideloaded install is impossible — Android only delivers install-referrer
data for Play Store installs, and Firebase Dynamic Links is discontinued. The
supported flow is one tap ("Open in app") after install, with the visible
code + Copy button as an always-works fallback.

## Hosting
- **Landing page:** GitHub Pages, project site → `https://priyanshu-prime.github.io/Vanshavali/`
- **APK:** GitHub Releases → `https://github.com/Priyanshu-Prime/Vanshavali/releases/latest`

## The invite URL (generated by the app, shared on WhatsApp)
```
https://priyanshu-prime.github.io/Vanshavali/?c=<CODE>&n=<url-encoded first name>
```
- `c` = the existing 6-char invite code (`SupabaseService.generateInviteCode`),
  resolved server-side via the `claim_profile_by_code` RPC.
- `n` = display name for friendly context (optional; url-encoded).

## App custom scheme (what the page's "Open in app" button fires)
```
vanshavali://invite?code=<CODE>
```
- App MUST also accept `?c=<CODE>` (both the page https form and the scheme form
  should parse identically).
- AndroidManifest.xml: add an intent-filter `scheme=vanshavali host=invite`
  (BROWSABLE + DEFAULT), alongside the existing `host=auth` one.

## Landing page behavior (bilingual EN/GU, low-tech-user UX)
1. Parse `c` and `n`.
2. Friendly invite context; show `n` if present.
3. Primary CTA **Download the app** → releases/latest.
4. **Open in app** → `vanshavali://invite?code=<CODE>` (JS attempt + graceful
   fallback text if nothing happens = app not yet installed).
5. Always show the code prominently + **Copy code** button.
6. High contrast, large targets, mobile-first. No external network calls
   (inline CSS/JS) so it loads on 2G.

## Logging (understand failures)
Instrument the journey via `ErrorReportingService` (writes to `error_logs`,
migration 008) + debugPrint breadcrumbs:
- link received, invite code parsed, routed to signup, claim success/failure.
- Failures → `ErrorReportingService.reportCaught(e, st, context: 'deeplink.*')`.

## CI/CD requirements
- `ci.yml`: trigger on **all** branch pushes + all PRs (not just main); keep
  gen-l10n + build_runner + analyze + test; **add a build job** (`flutter build
  apk --debug`) so compile breaks fail CI.
- `deploy-pages.yml`: publish `landing/**` to GitHub Pages on push to main.
- `release.yml`: on tag `v*`, build the APK and attach to a GitHub Release so
  `releases/latest` resolves (document the signing-secret requirement; fall back
  to manual upload for alpha if secrets absent).
- Local pre-push hook (`.githooks/pre-push`) running `flutter analyze &&
  flutter test`; document `git config core.hooksPath .githooks`.

## One-time owner steps (not automatable here)
- Enable GitHub Pages for the repo (source: the deploy workflow / gh-pages).
- Upload the current alpha APK to a GitHub Release (or add signing secrets so
  `release.yml` does it), so the page's Download button resolves.

## End-to-end test checklist

### Automated (headless, real local-Supabase backend)
- `test/services/deep_link_service_test.dart` — code extraction from both URL
  forms, `?c`/`?code`, malformed/missing, host gating; invite-text contents.
- `test/screens/auth/signup_prefill_test.dart` — SignupScreen renders a
  prefilled code in the field.
- `integration_test/flows/invite_deeplink_test.dart` — the app's own
  `buildInviteUrl` → `parseInviteCodeFromUri` round-trips (https + custom
  scheme), and the parsed code claims the seeded `TEST01`/Ramesh placeholder
  end to end. Run via `scripts/e2e/run_e2e.sh integration_test/flows/invite_deeplink_test.dart`.

### On-device (the intent → handler half a headless test can't reach)
Run `scripts/e2e/fire_invite_intent.sh [CODE]` against an emulator with the app
installed, then watch:
`adb logcat -s flutter | grep -iE 'deeplink|invite|claim'`

| # | Action | Expected result | Confirmed by log line |
|---|--------|-----------------|-----------------------|
| 1 | Fire `vanshavali://invite?code=TEST01` (script or a tapped link) | App opens on Sign Up, 6-char field pre-filled `TEST01` | `deeplink: link received` → `invite code parsed` → `routed to signup` |
| 2 | Complete sign up (email + password) | Lands on Home as **Ramesh** (claimed), not a new profile | `deeplink: claim attempt result: success` |
| 3 | Malformed code `vanshavali://invite?code=ZZ` | App opens signup, field NOT filled (invalid), no crash | `invite code parsed` absent / null |

### Full manual journey (the parts no tooling can drive)
1. **Generate + share** — in the app, open a placeholder's profile → Invite →
   share to WhatsApp. Message contains `https://priyanshu-prime.github.io/Vanshavali/?c=<CODE>&n=<name>` + the bare code.
2. **Tap the link (no app yet)** → landing page loads (bilingual), shows the
   code + Copy, a Download button, and Open-in-app.
3. **Download + sideload** the APK from the GitHub Release; allow "unknown
   sources".
4. **Tap "Open in app"** (or re-tap the WhatsApp link) → app opens on Sign Up
   with the code pre-filled → complete signup → claimed.
5. **Fallback** — if Open-in-app does nothing, the code + Copy button let the
   invitee type/paste it manually on the Sign Up screen. This path must always
   work even when deep linking fails.
